# Структура Карты контента

Администрирование и личные результаты разделены: `/admin` — пользователи, активность, использование функций, подключения и состояние сервиса; `/profile/dashboard` — дашборд текущего пользователя из карточки в профиле. Адрес `/dashboard` сохранён за воронками. Личный API `/api/account/dashboard` получает область только из проверенной сессии; глобальные показатели и административные права не нужны.

Главная показывает фокус и материалы дня. «Контент» объединяет план, банк идей и общую карточку. Календарь хранит размещения и отдельное разрешение на отправку. Продукты, CTA и воронки связывают материал с целью. Контекст хранит фактуру и источники. Профиль открывает управление подключениями агента. Админские API доступны разрешённым Telegram-аккаунтам после свежего входа.

## Клиент

React 18, TypeScript, React Router, Vite, Tailwind и существующие Radix/shadcn-компоненты. Маршруты — src/App.tsx. Рабочие страницы: /home, /content, /calendar, /products, /dashboard, /map, /context, /profile, /agents, /admin. Supabase и вход по email/Google не являются действующей архитектурой.

Основное состояние сохраняют useMainState и editorialContext. Контекст использует useContextPersistence: серверная ревизия, последовательная очередь, локальный черновик конкретного аккаунта и остановка записи при конфликте. История материалов и общий редактор описаны в docs/EDITORIAL_WORKSPACE.md.

## Сервер и данные

server/telegram-auth-server.mjs обслуживает API и собранные ресурсы. Prisma используется для моделей авторизации; pg — для редактора, очереди, агента и сессий. PostgreSQL проверяет сертификат Timeweb и имя сервера. Миграции: server/schema.mjs и отдельный ops/migrate.mjs.

cm_user_state содержит документы main, publications и context каждого пользователя. main/publications сохраняются совместной транзакцией с ревизиями, context — отдельной транзакцией с If-Match. cm_auth_sessions хранит хеши сессий и сроки административного допуска; старые подписанные cookies без серверной записи не принимаются. cm_agent_connections и cm_agent_actions обслуживают права, отзыв и повтор запросов MCP. Пользовательские маршруты не принимают произвольные внутренние ключи состояния.

## Отправка и агент

Агент читает и исправляет разрешённые сущности, но не утверждает и не отправляет публикации. Назначение даты сохраняет план. Threads использует существующую очередь и зарубежного отправщика; остальные форматы остаются ручными. Неопределённые отправки защищены от слепого повтора. Изменения инфраструктуры не назначают новые публикации.

## Защита и выпуск

request-security.mjs задаёт общий контроль источника, типа/размера запросов, ограничения частоты и защитные заголовки. session-store.mjs отзывает сессии и ограничивает админский допуск. Конфигурация production проверяется до запуска.

Приложение работает от Linux-пользователя karta и роли БД karta_runtime. Миграционное окружение и ключ резервирования доступны только root. Выпуски находятся в /opt/kartakontenta/releases, current указывает на проверенный. /api/health проверяет чтение рабочей таблицы без выдачи содержимого.

Шифрованные копии содержат только таблицы Карты, необходимые типы PostgreSQL, код и закрытую конфигурацию. Восстановление проверяется в отдельной karta_restore_... базе и не заменяет рабочую. Устройство — docs/BACKUPS.md. Настройка серверных файлов применяется при выпуске; наличие этих документов само по себе не запускает службу.
