# Karta Kontenta Do Not Repeat

## Ошибки, которые нельзя повторять

### 1. Огромные поля с маленьким текстом

Не делать inputs, selects и filters такими высокими, что воздуха сверху/снизу больше, чем самого текста.

Плохо:

- фильтры `Тип`, `Формат`, `Статус` как большие пустые блоки;
- dropdown row с одним словом и огромной высотой.

Лучше:

- компактная высота 36-44px;
- текст 12-15px;
- ровное вертикальное центрирование.

### 2. Горизонтальный scroll в dropdown

Dropdown никогда не должен вылезать за viewport и создавать нижний ползунок.

Особенно проверять:

- format selector;
- keyword picker;
- content picker;
- mobile modal dropdown.

### 3. Лишние helper-фразы

Не писать `Выберите слово...` внутри списка, если label уже говорит `Кодовое слово`.

Лучше:

- выбранное слово;
- compact list;
- add row `Новое слово...`.

### 4. Шестерёнка как отдельный высокий блок

Шестерёнка должна быть маленькой и рядом с названием секции.

Плохо:

- gear в отдельной вертикальной капсуле;
- gear ломает строку label.

Лучше:

- label `Тип продукта` + маленькая icon button рядом;
- в edit mode icon меняется на check.

### 5. Delete visible by default

Не показывать удаление всегда.

Удаление пользовательских типов/форматов/площадок/слов должно появляться только в edit mode и требовать подтверждения.

### 6. Disabled submit без подсказки

Не оставлять пользователя гадать, почему кнопка неактивна.

Если пользователь нажал disabled create:

- подсветить недостающие поля;
- показать короткую подсказку;
- сохранить мягкий стиль.

### 7. CRM на первом плане

Не делать таблицы, метрики и админку главным визуальным языком.

Главное:

- продукты;
- контент;
- CTA;
- воронки;
- карта связей.

Админка — второй слой.

### 8. Слишком декоративный SaaS

Не добавлять:

- blob/orb;
- большие декоративные градиенты;
- случайные иллюстрации;
- oversized hero inside app;
- много фиолетовых плашек.

Лучше:

- белая поверхность;
- тонкая линия;
- soft violet selected state;
- compact action;
- понятная связь сущностей.

### 9. Разные стили чипов

Типы продукта и площадки контента должны быть одной семьи.

Плохо:

- разные радиусы;
- разные высоты;
- разный font-weight;
- случайные иконки.

Лучше:

- один compact chip pattern;
- одинаковая edit-модель;
- одинаковое selected/disabled поведение.

### 10. Фейковая админка

Не добавлять больше фейковых метрик ради красоты.

Если данных нет:

- показать пустое состояние;
- показать `не подключено`;
- подготовить место под API.
