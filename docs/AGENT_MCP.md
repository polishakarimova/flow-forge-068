# Агент в «Карте контента»

Раздел `/agents` выдаёт одноразовый код на 10 минут с правами выбранного владельцем аккаунта. Агент работает с настоящими сценариями, продуктами, воронками и календарём; изменения используют существующую транзакцию редактора. До пяти активных подключений на аккаунт. «Отключить» отзывает и access, и refresh, и неиспользованный код.

## Подключение в Codex / Claude / другом локальном MCP-клиенте

Сначала установите зависимости этого репозитория (`npm ci`). MCP-процесс:

```text
node /absolute/path/flow-forge-068/server/karta-mcp.mjs --url https://kartakontenta.ru --account my-agent
```

Пример Codex config.toml:

```toml
[mcp_servers.karta_kontenta]
command = 'C:\Program Files\nodejs\node.exe'
args = ['C:\Users\polin\CodexProjects\flow-forge-068\server\karta-mcp.mjs', '--url', 'https://kartakontenta.ru', '--account', 'codex']
startup_timeout_sec = 20
tool_timeout_sec = 60
```

Для другого компьютера замените оба пути. Для другого агента выберите другое `--account`, чтобы у каждого подключения был свой доступ.

Пример клиента с JSON-конфигурацией:

```json
{"mcpServers":{"karta-kontenta":{"command":"node","args":["/absolute/path/flow-forge-068/server/karta-mcp.mjs","--url","https://kartakontenta.ru","--account","claude"]}}}
```

После загрузки MCP агент вызывает `karta_connect` с кодом из приложения. Сам код не нужен в конфигурации. Секреты не возвращаются в ответ инструмента. В Windows они защищены DPAPI для текущего пользователя, вне репозитория и базы знаний (`%LOCALAPPDATA%/KartaKontenta/agents`). В Unix используется закрытый файл 0600. Мост обновляет токены и повторяет запрос с тем же requestId после 401; профиль блокируется на время операции, в том числе между процессами.

## API и удалённый MCP

- `POST /api/agent/connect` с `{"code":"XXXXX-XXXXX"}` → access_token на час и refresh_token на 30 дней.
- `POST /api/agent/refresh` с `{"refresh_token":"..."}` → новая пара токенов. Старые токены больше не принимаются.
- `GET /api/agent/me` → подключение и его права.
- `GET /api/agent/tools` → разрешённые инструменты с JSON Schema.
- `POST /api/agent/actions` с `{"name":"karta_overview","arguments":{}}` → результат инструмента.
- `POST /api/agent/mcp` → настоящий Streamable HTTP MCP на официальном SDK.

Последние четыре маршрута требуют `Authorization: Bearer <access_token>`. MCP HTTP работает без серверных сессий, с JSON-ответами. Прямой HTTP-клиент сам хранит и обновляет токены; автоматическое обновление реализовано в stdio-мосте. OAuth discovery/registration в этой версии нет: облачным клиентам, которые требуют OAuth, нужен отдельный OAuth-слой. Передача одного текста с кодом не устанавливает MCP в клиенте автоматически; API доступен агентам с HTTP-инструментами.

Управление подключениями работает только через текущую Telegram-сессию пользователя: `GET/POST /api/agent/connections`, `DELETE /api/agent/connections/:id`. Записывающие запросы управления проверяют Origin приложения. Коды и токены в серверной базе хранятся только как SHA-256-хеши.

## Возможности и сохранение

| Инструмент | Право | Действие |
|---|---|---|
| karta_overview, karta_list, karta_get | read | Количество, поиск, списки, полные тексты и контекст аккаунта |
| karta_save_idea | content | Создание/правка/архив идеи |
| karta_create_post, karta_update_post | content | Сценарий, экраны, CTA, готовые файлы и ссылки |
| karta_save_metrics | content | Фактические ручные результаты |
| karta_save_product | products | Продукты, описания, цены, ссылки и архив |
| karta_save_funnel | funnels | Кодовые слова, CTA, этапы, связи, путь и приостановка |
| karta_schedule_post, karta_save_focus, karta_save_variants | planning | Календарь, фокус недели/дня, группы альтернатив |

Чтение возвращает `revisions.main` и `revisions.publications`. Каждый запрос на запись требует эти версии и `requestId` (новый UUID для нового действия). Повтор того же тела с тем же UUID возвращает сохранённый результат без второго поста. Использование UUID для другого тела и устаревшие версии дают 409. Новый текст после конфликта должен опираться на заново прочитанную версию, а не повторяться с автоматически подставленной свежей ревизией.

Создание поста и новой идеи выполняется целиком в одной транзакции. Ошибка ссылки не оставляет пустую идею. Правки поста сохраняют пропущенные поля. Для сценария с экранами исправляйте `blocks`; общий `body` без изменения экранов отклоняется. Опубликованные экраны и отправляемые/неопределённые публикации защищены прежними проверками приложения. При отзыве доступ проверяется повторно под блокировкой внутри транзакции. Журнал правок фиксируется вместе с сохранением, без токенов и текста запроса.

У агента нет инструментов удаления всего аккаунта, чтения чужих кабинетов, изменения подключения соцсетей, утверждения отправки или самой отправки. Назначение даты сохраняет план и не утверждает публикацию. Расписание, фоновые задачи и самостоятельные оповещения эта интеграция не создаёт.
