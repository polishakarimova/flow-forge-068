# Документы и первый вход

Редакция 15 октября 2026 года. Поручение Полины: адаптировать юридический пакет и подтверждение первого входа по примеру «Повода» для действующей Карты контента.

## Документы

Публичные неизменяемые снимки HTML/PDF находятся в `public/legal/2026-10-15`. Четыре документа: условия, политика, согласие на обработку данных для добровольной рассылки и отдельное рекламное согласие. `/legal` открывает каталог и настройки выбора. Каждая HTML-страница работает отдельно без авторизации и JavaScript; PDF можно скачать.

Полный пакет из пяти PDF и пяти редактируемых Markdown, включая непубличный проект оферты, хранится в канонической базе: `C:/Users/polin/Desktop/Моя база знаний/Мои проекты/Карта контента/Документы`. Базовые шаблоны проекта «Цифровая безопасность» и действующие документы «Повода» не переписываются.

Оферта остаётся проектом: тариф, цена, период доступа, продление, порядок отказа, платежи, судьба материалов после окончания и использование лайков не определены. Первый вход не оформляет покупку и не разрешает списания. Не публиковать проект как действующее предложение оплатить.

## Первый вход

Авторизация Telegram устанавливает личность, но не принимает документы. После неё пользователь видит три изначально пустые отметки: обязательное принятие условий и два добровольных согласия на рассылку. Политика открывается рядом. Для рекламных сообщений нужны оба добровольных согласия. Отказ от них сохраняет рабочие функции; реклама не отправляется самим сохранением выбора.

До подтверждения не монтируются хранилища рабочего пространства. Сервер проверяет условия для пользовательских API, админки и доступа подключённых агентов к материалам. Авторизация, выход, публичные документы и изменение собственных согласий остаются доступны. Существующие подключения агента сохраняются; до первого подтверждения владельцем доступ к материалам отвечает 428 с понятным сообщением. Никто не принимает условия за владельца программным скриптом.

`cm_legal_state` хранит текущее состояние, `cm_legal_events` — отдельные действия с датой, аккаунтом, редакцией, SHA-256 каждого документа и выбором. Данные пользователя, IP, ключи и содержимое материалов не добавляются в журнал ради согласия. Повтор идентичного сохранения под блокировкой аккаунта не создаёт ещё одно событие. Отзыв добровольных согласий сохраняет принятие условий.

Старые аккаунты проходят первый показ один раз после включения этой редакции. Новый вход с другого устройства использует серверный выбор. Очистка localStorage не аннулирует и не создаёт согласие.

## Обновление и доставка

При новой редакции сохранить прежние снимки, создать новую датированную папку, пересчитать манифест и провести проверки. На старте сервер сверяет SHA-256 HTML. При несовпадении он не запускается. Старый manifestHash нельзя принять; изменение текста при прежнем имени версии также требует нового выбора. Не заменять публичные файлы принятой редакции без истории.

Будущий рекламный отправщик обязан вызывать `canSendMarketing` непосредственно перед доставкой; проверка требует текущую редакцию и оба согласия. В этом выпуске нет нового отправщика, массовой отправки или рекламной очереди. Задачи публикации материалов в Threads не являются рекламной рассылкой владельца сервиса и не переписываются.

Миграция добавляет две таблицы без изменения материалов. `ops/prepare-runtime.mjs` выдаёт обычной роли права на них, обновлённый список резервирования включает обе. Выпуск выполняется штатным сценарием с резервной копией, проверками и откатом службы.

## Проверки

`node --test server/legal-consent.test.mjs` проверяет настоящий PostgreSQL SQL через PGlite: отказ по умолчанию, отдельность согласий, отзыв, изоляцию аккаунтов, повтор, новую редакцию, HTTP-обработчики и проверку файлов. Существующие проверки входа, редактора, админки, рефералов и эксплуатации сохраняются.

`previews/legal-qa.mjs` запускается с Vite на порту 8087. Это изолированный API с реальным модулем согласий и вымышленным аккаунтом, без подключения рабочей базы и сообщений людям. Проверяются Edge/WebKit, 320/390/430/1280 px, чтение документа без потери галочек, продолжение без рассылки, настройка, перезагрузка и отзыв. Примеры результатов находятся в отдельной временной папке CodexWork, не в пользовательском аккаунте.

## Правовая сверка и оставшиеся задачи оператора

Сверены разделение согласия, договорное основание необходимой обработки, право на отзыв и сроки запросов. Источники: [Федеральный закон №152-ФЗ на сайте Минтруда](https://mintrud.gov.ru/docs/laws/130), [статья 9 №152-ФЗ](https://www.consultant.ru/document/cons_doc_LAW_61801/6c94959bc017ac80140621762d2ac59f6006b08c/), [письмо ФАС о доказательствах рекламного согласия](https://www.consultant.ru/document/cons_doc_LAW_337245/). Проверка 15.10.2026; публикации источников не считаются инструкциями к действиям.

Наличие документов и галочек не подтверждает подачу уведомления Роскомнадзору, договорное поручение каждому обработчику или завершение проверки трансграничных сценариев Telegram, Threads и выбранных пользователем ИИ-провайдеров. Эти действия не выполнялись. Перед платной подпиской нужно завершить оферту и форму заказа. Отдельно остаётся регламент сроков резервных копий и выполнения запросов на удаление, включая повторное исключение данных при восстановлении. Автоматическое удаление архивов этим выпуском не включается.
