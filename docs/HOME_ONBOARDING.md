# Экскурсия по главной

Онбординг объясняет разделы на существующем главном экране. Переходы между рабочими страницами выполняются после закрытия экскурсии обычной навигацией.

## Поведение

- После загрузки главной новый для этого устройства аккаунт получает приглашение пройти экскурсию. Прямые ссылки на календарь, материал и другие разделы остаются доступны без автоматического тура.
- Приветствие → главная → контент → календарь → продажи → контекст → профиль → завершение.
- На телефоне «Продажи» показывают вход в продукты, воронки и карту. На компьютере подсвечиваются три соответствующие строки боковой панели.
- Доступны пропуск, крестик, предыдущий/следующий шаг, Escape и стрелки клавиатуры. Enter активирует выбранную кнопку. Фокус остаётся в окне экскурсии.
- Пропуск, крестик и завершение запоминаются отдельно для аккаунта в `karta-home-tour:v1:<userId>`. Это память устройства. При недоступности этого ключа используется память текущего открытия приложения.
- Повторный запуск: «Экскурсия по разделам» на главной, «Обучение» в профиле или боковой панели. Запуск из другого раздела возвращает на главную.
- Закрытие возвращает прокрутку и фокус. При уходе с главной/выходе из аккаунта окно удаляется вместе с подсветкой.
- Тур не вызывает операции записи API.

## Оформление и будущая переработка экрана

Подача вдохновлена онбордингом ПОВОДА: светлое стеклянное приветствие, рукописные заголовки, тонкая обводка и изогнутая стрелка. Используются действующие фиолетовые переменные Карты; основной текст остаётся Inter. Caveat размещён локально вместе с лицензией OFL.

Тексты, порядок и память находятся в `src/lib/homeTour.ts`. Компонент и стили изолированы в `src/components/OnboardingTour.tsx` и `onboarding-tour.css`. При переработке главной переносите `data-tour` на новые элементы: `home`, `content`, `calendar`, `sales`, `context`, `profile`. Видимость мобильной/настольной версии определяется по настоящим элементам, содержимое `main` имеет приоритет перед дублирующей навигацией.

Размеры целей считываются при смене шага, прокрутке, изменении viewport и размеров элементов. Диалог учитывает существующие безопасные зоны Telegram, уменьшение движения и системные контрастные цвета. Размываются соседние ветви DOM, а цель и её содержимое остаются чёткими, включая WebKit.

## Проверка

`TOUR_QA_BASE=http://127.0.0.1:8087 node src/test/home-tour.e2e.cjs` — изолированные API-ответы, без настоящего аккаунта и пользовательских материалов. `TOUR_QA_DIR` задаёт необязательное место снимков. Нужны Edge и установленный Playwright WebKit.

Проверяются восемь шагов на 320/360/390/430/1280 px, отсутствие пересечений подсказки и цели, чёткость выделения, сохранение результата, ручной повтор, клавиатура, запуск из профиля, безопасные зоны Telegram, отдельные аккаунты, закрытие/пропуск, ошибка загрузки, гостевой вход, ограниченная память и прямой вход в календарь.

Существующие проверки домашней навигации и Telegram получают маркер завершённого тура в своих тестовых аккаунтах; проверка ручного обучения использует новый заголовок.
