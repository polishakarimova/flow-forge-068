# Сценарии, готовые файлы и безопасный импорт

Все текущие входы карты, плана и календаря открывают MaterialCard. Текст многоэкранного материала хранится в blocks; body — объединённое представление. Опубликованные экраны нельзя менять, удалять или переставлять. Остальные экраны можно редактировать.

## Готовые файлы

material.assets: массив до 30 элементов `{ id, label, kind, url, downloadUrl? }`.
kind: video, carousel, folder, other. Ссылки только HTTP(S), без credentials. Внешние страницы открываются с noopener/noreferrer. Никакого копирования файлов, загрузки в Google Drive или изменения доступа приложение не делает.

Для обычного Drive file URL кнопка скачивания строится с сохранением resourcekey. Для folder доступно открытие папки; скачивание выбирается в Google Drive. Для другого сервиса прямую ссылку можно указать отдельно. Внешний сервис может потребовать вход, права доступа или подтверждение большого файла.

В будущем агент сможет записывать assets существующему материалу с id и revision, а затем вернуть ссылку `/content?material=ID`. Авторизация агента и автоматическая запись не подключены.

## Сохранение

POST /api/content-workspace использует существующую сессию пользователя. Запрос содержит type, input, revisions. material.save и idea.save дополнительно принимают revision сущности: устаревший текст отвергается даже при свежем снимке рабочей области. Для независимых правок совпадение revision сущности позволяет сохранить без конфликта всего календаря. Структурные операции продолжают использовать версии рабочей области. Блокировки отправки Threads сохранены.

Черновики форм сохраняются локально по аккаунту и ID для восстановления после перезапуска. Это резерв на данном устройстве; подтверждённые данные хранятся на сервере. Конфликтующий материал можно сохранить отдельной копией. История ограничена 30 версиями; восстановление открывает выбранную версию в редакторе и требует обычного сохранения.

GET поддерживает ETag/304. Видимая вкладка обновляет данные каждые 20 секунд и при возвращении фокуса, не заменяя несохранённый текст.

## Ручной пакет черновиков

bundle.import принимает `{ideas:[{sourceKey,title,thesisPlan,formatIds,source,tags,materials:[{sourceKey,platformId,title,body,blocks,visual,motion,resources,cta}]}],slots:[{sourceKey,title,variantSourceKeys,recommendedSourceKey,reason}]}`.

До 100 идей, 200 сценариев и 100 групп. Повторный sourceKey не перезаписывает существующие правки. Импорт атомарный, даты и утверждения не переносит, в очередь отправки ничего не добавляет. Это ручной импорт, не интеграция агента.

## Ограничения

История пока хранится в основном JSONB документе. ETag уменьшает повторный трафик, версии сущностей уменьшают несвязанные конфликты. Отдельное хранение истории и пагинация понадобятся при росте объёма; нагрузочный тест тысяч материалов не проводился. Путь воронки — редактируемая последовательность шагов и условий, не исполнитель автоматизации и не конструктор произвольного графа ветвлений.
