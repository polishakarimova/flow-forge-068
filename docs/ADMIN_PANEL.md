# Админ-панель Карты контента

Дата: 15 октября 2026. Запрос Полины: развить админ-панель по примеру ПОВОДА с метриками Карты и постоянной кнопкой «Admin панель» под строкой ввода бота.

## Экраны

`/admin`: обзор, пользователи, система. Периоды 7/30/90 дней относятся к регистрациям, активности и действиям агентов. Наполнение, статусы, связи и очередь показывают состояние на момент обновления. Время — Europe/Kaliningrad. Есть обновление, поиск пользователей, фильтры и страницы по двадцать записей.

Метрики: зарегистрированные и активные пользователи; освоение продуктов/контента/воронок; текущие количества; статусы и форматы материалов; связи с существующими продуктами и воронками; CTA; утверждение текущей версии сценария; отдельные отметки календаря; ручные результаты контента; активные агенты и последние сохранения; реальные статусы очереди Threads; настройки отправки и состояние базы.

Активность — последний вход или изменение main/publications, включая сохранения агентом. Это не время просмотра экранов. График входов считает уникальных пользователей в день по cm_auth_sessions; неизвестная история не восстанавливается. Архивные идеи и их материалы исключены из текущего наполнения. Материалы и экраны календаря не складываются: один материал может иметь несколько экранов. Ручные продажи контента не являются выручкой сервиса. Незаполненные результаты показываются прочерком. Оплата и рассылки не подключены; панели не включают их автоматически.

## Доступ

API сохраняет серверную проверку ADMIN_TELEGRAM_IDS, подписанную отзываемую сессию и свежий административный допуск: 15 минут, 5 минут бездействия. Локальный экран также скрывает показатели по этим срокам. В Telegram однократно пробует обновить сессию через проверяемую сервером initData; отказ не превращается в бесконечный цикл. В браузере остаётся штатный вход через бота. Маршрут панели доступен для показа входа без загрузки личного редактора; это не открывает её API. Ссылка в боковом меню видна только администратору.

API читает согласованный снимок в read-only транзакции. Контекст, тела материалов, история текстов, результаты инструментов, токены, хеши доступа и технические ошибки отправщика не выдаются. Из журнала агентов выбираются только название подключения, инструмент и время. Полные технические журналы ошибок и проверка резервных копий в панель не добавлены.

## Кнопка бота

Нижняя reply-клавиатура: `Admin панель`, `is_persistent=true`, `resize_keyboard=true`, `one_time_keyboard=false`. Показывается только разрешённому отправителю в его личном чате после `/start` или `/admin`. Нажатие возвращает inline Web App-кнопку на `/admin` со штатной Telegram-авторизацией. Повторный вход не зависит от старого одноразового login token. Обычная кнопка открытия Карты и меню слева сохранены. Команды `/admin`, `/start admin` также работают.

Два шага выбраны намеренно: Mini Apps из reply-клавиатуры не получают подписанную initData, а inline-кнопка получает её. Установка нижней кнопки в существующем чате требует одного сообщения бота; это не рассылка пользователям. Документация: [Telegram ReplyKeyboardMarkup](https://core.telegram.org/bots/api#replykeyboardmarkup), [WebAppInitData](https://core.telegram.org/bots/webapps#webappinitdata).

## Проверки

`npm run test:admin`, `node src/test/admin.e2e.cjs`, TypeScript, сборка, общий lint. Новый SQL-тест выполняется с PGlite. Браузерный тест использует только искусственные аккаунты и перехваченные API; проверяет 360/390/430/1280 px, периоды, вкладки, поиск, страницы, отказ, повтор и обновление Telegram-сессии. Скриншоты — previews/admin-review, не включаются в Git.

`ops/admin-release-check.mjs --http` на сервере проверяет реальный SQL, 401 без сессии, 200 администратора, 403 обычного аккаунта, истечение допуска и неизменность cm_user_state. Временные проверочные сессии удаляются в finally; секреты в вывод не попадают. Без --http выполняется только чтение базы и проверка сохранности.
